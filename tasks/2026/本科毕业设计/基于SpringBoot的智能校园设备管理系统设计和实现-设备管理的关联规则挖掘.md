## 一、最匹配：大学建筑设施维护数据集 ⭐⭐⭐⭐⭐

这是**与你研究方向最匹配**的数据集，来源权威、规模大、字段丰富。

### Comprehensive Maintenance Dataset of Building Facilities

| 属性 | 内容 |
|------|------|
| **来源** | ScienceDirect (Data in Brief期刊) |
| **数据范围** | 美国和加拿大12所大学，2002-2021年 |
| **核心内容** | 计划性预防维护(PPM) + 非计划性维护(UPM)的工作订单 |
| **数据规模** | 完整覆盖20年运维数据 |
| **DOI** | 10.1016/j.dib.2024.110845  |
| **公开状态** | 完全开源 |

**数据结构（9个属性组）**：
- **大学信息**：地理位置、规模分类
- **建筑信息**：建筑类型、建成年代、面积
- **系统/子系统/组件**：三级设备分类体系（基于FMUCO统一编码）
- **工单信息**：故障类型、响应时间、完成时间、紧急程度
- **成本数据**：人工成本、材料成本
- **劳动力数据**：维修人员、工时
- **天气数据**：故障发生时的天气条件

**为什么高度匹配**：
1. **场景完全一致**：大学校园建筑设施管理，与你的系统完全吻合
2. **数据维度丰富**：包含设备类型、故障类型、时间、成本等多维信息，可直接用于关联规则挖掘（如 {空调系统, 夏季} → {高频率故障}）
3. **权威学术来源**：发表在Data in Brief，数据质量有保障

**获取方式**：访问ScienceDirect搜索DOI: 10.1016/j.dib.2024.110845，或直接下载


## 二、直接相关：照明能耗与占用数据（论文方法论参考）

这篇论文**不是公开数据集**，但提供了完整的研究方法论和实验数据参考。

### Data association mining for identifying lighting energy waste patterns in educational institutes

| 属性 | 内容 |
|------|------|
| **来源** | Energy and Buildings期刊 (Elsevier) |
| **发表时间** | 2013年（方法论经典，仍被广泛引用） |
| **数据内容** | 3间教室一整年的占用传感器数据 + 照明能耗数据 |
| **发现** | 关联规则挖掘发现：若遵循规则，可节省**高达70%**的照明能耗  |

**核心研究结论**：
- 关联规则格式示例：`{无人占用, 时间段=深夜}` → `{照明开启}`（表示能源浪费）
- 通过规则挖掘，可发现不同学期、不同时间段的浪费模式
- 方法可迁移至你的设备管理场景（如空调、电脑、投影仪）

**参考价值**：如果需要在论文中展示方法学依据，这篇论文的框架可以直接引用

## 六、在你的系统中的使用方法

### 6.1 关联规则挖掘的目标
在校园设备管理系统中，你可以挖掘以下类型的规则：

| 规则类型       | 示例                                  | 应用价值     |
| ---------- | ----------------------------------- | -------- |
| **设备故障关联** | `{空调故障}` → `{服务器温度升高} (置信度85%)`     | 故障传播路径识别 |
| **时间模式**   | `{时间段=凌晨2-4点, 设备=投影仪}` → `{异常开启}`   | 能源浪费检测   |
| **维护关联**   | `{未做预防性维护}` → `{故障率+300%}`          | 维护计划优化   |
| **用户行为**   | `{用户=信息学院, 设备=3D打印机}` → `{使用时长>4h}` | 资源分配优化   |

### 6.2 算法实现流程（SpringBoot集成）

```java
// 1. 从数据库提取事务数据
List<Transaction> transactions = getWorkOrderTransactions();

// 2. 调用Python关联规则挖掘服务（通过REST API）
String rules = restTemplate.postForObject(
    "http://python-service/apriori", 
    transactions, 
    String.class
);

// 3. 解析规则并存入数据库
List<AssociationRule> ruleList = parseRules(rules);
ruleRepository.saveAll(ruleList);

// 4. 实时告警：当触发条件满足时推送
if (detectRuleMatch(currentEvent)) {
    alertService.push(rule.getConsequent());
}
```

**关键技术选型**：
- **Python端**：mlxtend库的apriori + association_rules函数
- **Java端**：SpringBoot + RestTemplate调用Python服务
- **数据存储**：MySQL存储原始工单 + Redis缓存挖掘出的规则
- **可视化**：ECharts绘制规则关系图

## 七、如果数据获取有困难

如果上述数据集的申请流程较长或受限，可以考虑：

| 方案 | 方法 | 优势 | 劣势 |
|------|------|------|------|
| **仿真生成** | 编写Python脚本生成模拟工单数据 | 完全可控，可自定义规则 | 缺乏真实数据说服力 |
| **公开benchmark** | 使用UCI的"超市购物篮"数据集验证算法 | 数据易得 | 场景不匹配 |
| **自行采集** | 在自己学校部署系统原型采集日志 | 场景最匹配 | 周期长、数据量小 |

**我的建议**：优先尝试获取**大学建筑设施维护数据集**（DOI: 10.1016/j.dib.2024.110845），这是最权威且最匹配的来源。如果获取有困难，**FabLab设备使用数据集**（DOI: 10.5281/zenodo.17865416）作为备选也非常合适。
