## 一、为什么选择“知识图谱+引导式诊修推荐”？

与传统推荐相比，知识图谱驱动的诊修推荐有以下核心优势：

| 对比维度     | 传统推荐方法         | 知识图谱+引导式诊修             |
| -------- | -------------- | ---------------------- |
| **推荐依据** | 历史购买/服务记录      | 故障症状→原因→方案的因果关系链       |
| **可解释性** | 弱（“因为您之前做过保养”） | 强（“因为您的电池电压异常+充电次数过多”） |
| **诊断深度** | 单层推荐           | 多层级因果推理                |
| **交互方式** | 被动接收           | 主动引导（追问缺失信息）           |
| **动态调整** | 基于反馈           | 基于推理路径+用户反馈双驱动         |

**核心价值**：从“推荐服务”升级为**“推荐诊断方案”**，更适合新能源汽车售后服务场景。

## 二、核心技术路线

### 路线一：知识图谱 + 协同过滤融合推荐（⭐⭐⭐⭐⭐ 首选）

这是**2025年最新专利技术**，由北京卡文新能源汽车有限公司申请，专门针对“引导式诊修策略推荐”。

**专利核心内容**：

| 技术环节       | 实现方式                           |
| ---------- | ------------------------------ |
| **故障现象识别** | 基于预设的故障文本特征提取模型，从用户输入中提取故障现象实体 |
| **知识图谱查询** | 基于车辆故障诊修知识图谱，查询与故障现象匹配的故障原因实体  |
| **概率排序**   | 基于协同过滤策略，确定各故障原因的发生概率排序        |
| **策略推送**   | 将最大概率原因对应的诊修策略推送给用户            |

**专利的核心创新**：解决了“无法对故障原因进行概率排序导致推荐的诊修方案并非最优”的问题，**实现了基于故障原因可能性和维修成本的优化推荐**，并支持**根据用户反馈动态调整诊修方案**。

**技术实现架构**：
```
用户输入（故障描述）
    ↓
故障文本特征提取（预设模型/LLM）
    ↓
知识图谱查询（匹配故障现象→故障原因实体）
    ↓
协同过滤概率排序（历史案例+相似度计算）
    ↓
诊修方案推荐（综合考虑可能性+维修成本）
    ↓
用户反馈 → 动态调整策略（闭环优化）
```

**为什么首选这条路线**：
- 有**完整的专利技术文档**支撑
- 算法组合清晰：**知识图谱（存储因果关系）+ 协同过滤（概率排序）**
- 工程可实现性高
- 可直接作为论文的核心算法创新

### 4.2 知识图谱设计（Neo4j）

**关系类型**：
```

(诊修方案) -[适用于]-> (车型)
(故障原因) -[发生概率]-> (概率值)  // 协同过滤输出
```

### 4.3 协同过滤概率排序算法

**算法原理**（基于专利CN120410509A）：

```python
# 伪代码：基于协同过滤的故障原因概率排序
def rank_fault_causes(fault_symptom, kg, historical_cases):
    """
    输入：
        fault_symptom: 故障现象实体
        kg: 知识图谱
        historical_cases: 历史诊修案例
    输出：
        排序后的故障原因列表（含概率）
    """
    # 1. 从知识图谱获取候选故障原因
    candidates = kg.query(
        f"MATCH (s:症状 {{name:'{fault_symptom}'}})-[:表现为]->(c:原因) RETURN c"
    )
    
    # 2. 基于历史案例计算各原因的概率
    for cause in candidates:
        # 统计该原因在历史案例中的出现次数
        count = historical_cases.count(cause)
        # 计算条件概率 P(原因|症状)
        prob = count / historical_cases.total_count(symptom)
        cause.probability = prob
        
        # 可选：加入维修成本因子
        cause.cost_factor = get_repair_cost(cause.repair_plan)
        cause.score = prob * (1 - cost_factor)  # 综合考虑概率和成本
    
    # 3. 按综合得分排序
    return sorted(candidates, key=lambda x: x.score, reverse=True)
```

### 4.4 与SpringBoot系统的集成

```java
// SpringBoot Controller
@RestController
@RequestMapping("/api/diagnosis")
public class GuidedDiagnosisController {
    
    @Autowired
    private Neo4jTemplate neo4jTemplate;  // 知识图谱访问
    
    @Autowired
    private DiagnosisService diagnosisService;
    
    @PostMapping("/guided")
    public ResponseEntity<DiagnosisResult> guidedDiagnosis(
            @RequestBody UserQuery query) {
        // 1. 语义理解 + 实体抽取
        FaultEntity entity = nlpService.extractFaultEntity(query.getDescription());
        
        // 2. 知识图谱查询候选原因
        List<FaultCause> causes = diagnosisService.queryCausesFromKG(entity);
        
        // 3. 协同过滤概率排序
        List<RankedCause> ranked = diagnosisService.rankByProbability(causes, query.getVehicleId());
        
        // 4. 生成推荐方案
        DiagnosisResult result = diagnosisService.generateRecommendation(ranked);
        
        // 5. 记录日志（用于反馈闭环）
        logService.saveDiagnosisLog(query, result);
        
        return ResponseEntity.ok(result);
    }
}
```
